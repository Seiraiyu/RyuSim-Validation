# Finding: RyuSim 2.0.5 stale continuous-assign propagation breaks VeeR-EL2 branch targets

**Date:** 2026-08-08
**Filed upstream:** [Seiraiyu/RyuSimAlt#306](https://github.com/Seiraiyu/RyuSimAlt/issues/306)
**Phase impact:** Native testbench migration Phase 1 stopped at Task 7 (`make test-hello`); Tasks 1–6 and the runner change (Task 8) are complete and verified. No repo-side workaround exists.

## Symptom

`rtlmeter_tests/VeeR-EL2` native `tb_top` compiles clean under RyuSim 2.0.5
(21.5 min, `obj_dir/build/tb_top_sim`), but `make test-hello` never prints
`TEST_PASSED`:

- **Default (IEEE X-init):** sim wedges at 100% CPU with no output — actually
  crawling at ~40 cycles/s in X-churn (830 MB VCD for 13k cycles).
- **`--no-x-init` (Verilator-like zero-init):** fast, deterministic
  `-TEST_FAILED` at sim time 1450.

## Root cause

RyuSim 2.0.5 scheduling bug, minimized to:

```systemverilog
module repro
  ( input  [11:0] a,
    output [30:0] d );
  wire c;
  assign {c, d[11:0]} = {1'b0, a} + {1'b0, 12'h01b};
  assign d[30:12]     = c ? 19'h40000 : 19'h3ffff;
endmodule
```

When `repro` is instantiated (any non-top instance), the second assign
evaluates with a **stale `c`** — one update behind the sibling concat-LHS
assign that produces it. The same two assigns at top level are correct.
Isolation matrix (zero-based vs `[31:1]`-style ranges: no difference;
port vs internal net: no difference):

| Variant | Result |
|---|---|
| Same shape at top level (no instance boundary) | pass |
| Plain producer (`assign c = a[11];`) + split consumer | pass |
| Concat-LHS producer + whole-vector consumer | pass |
| Concat-LHS producer + split part-select consumer, in an instance | **fail** |

This is exactly `rvbradder` (`rtl/beh_lib.sv:496`), VeeR's branch-target
adder: `dout[31:13]` selects among `pc`/`pc+1`/`pc-1` using `cout` from the
sibling `{cout,dout[12:1]} = pc[12:1] + offset[12:1]` — so **every taken
branch whose 13-bit low-add carries out gets a PC off by ±0x2000**.

EXECUTION_TRACE of hello (zero-init debug build) — dies on the *first taken
branch* of the program:

```
83 : #15 0 80000036 fe029be3  ; bne t0,zero,0x8000002c   <- taken, cout should be 1
89 : #16 0 7fffe02c 00000000  ; .short 0                  <- lands at target-0x2000 (stale cout=0)
106: #17 0 80000120 00004505  ; c.li a0,1                 <- illegal-instr trap; handler writes TEST_FAILED
```

Under default X-init the stale `cout` is X, poisoning the PC — the
apparent hang.

## What was ruled out on the way

- `$readmemh` hierarchical load into `bit [7:0] mem[bit[31:0]]` associative
  arrays **works** (probe loaded all 383 bytes of hello.hex across both
  `@`-sections).
- DUT/TB/program parity vs upstream pins is exact (all md5s and diffs clean;
  `rtl/tb_top.sv` was already identical to the rtlmeter pin).
- The Makefile/flags are correct; compile is clean (5 benign clang warnings).

## Secondary findings

1. **Upstream rtlmeter bit-rot:** `tb_top.sv` under `-DEXECUTION_TRACE` uses
   undeclared `fd` (`tb_top.sv:690`) — doesn't compile anywhere; we patched a
   scratch copy (`integer tp, el, fd;`) for the debug build only. Consider
   reporting to verilator/rtlmeter.
2. `tb_top_sim --help` (any unknown arg) silently starts the simulation
   instead of printing usage.
3. rtlmeter's harness injects `rtl/__rtlmeter_top_include.vh` (instantiating
   its `__rtlmeter_utils` cycle-counter/trace module) into every design's top;
   our port stubs it empty (`tb/__rtlmeter_top_include.vh`) since the Makefile
   replaces that harness. The plan's assumption that `veer_wrapper.sv` was
   cocotb-only was wrong — upstream's descriptor lists it and `tb_top`
   requires it; it stays in `RTL_SOURCES`.

## Debug recipe (for the retest after the fix)

- RyuSim installs to `~/.ryusim/bin` (not on PATH by default).
- Debug variants compile with the same source list:
  `ryusim compile <sources> --top tb_top -Irtl -Irtl/default -Itb -o <dir> [--no-x-init] [-DEXECUTION_TRACE] [--trace-vcd --max-time 1ms]`
  (EXECUTION_TRACE needs the `fd` patch above; exec log lands in `exec.log`.)
- Retest gate: `make test-hello` in `rtlmeter_tests/VeeR-EL2` → expect VeeR
  console banner + `TEST_PASSED`, then resume Phase 1 Task 7 (commit gates
  unchanged).
